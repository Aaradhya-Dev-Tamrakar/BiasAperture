## 1. Verification Lifecycle

Every technical claim in BiasAperture progresses through explicit, auditable states, including a formal failure branch (`INVALIDATED`):

```mermaid
flowchart LR
    A["1. ASSERTED\n(Hypothesis from literature / AI reconnaissance)"] -->|Primary source inspection / Tensor probe| V["2. VERIFIED\n(Confirmed via direct evidence / external file)"]
    V -->|Codified in automated pytest / deterministic script| R["3. REPRODUCIBLE\n(Passing mathematical/contract test in CI)"]
    R -->|Integrated into production codebase| I["4. IMPLEMENTED\n(Live in core pipeline WP2–WP5)"]
    I -->|Benchmark execution on full FairFace dataset| VAL["5. VALIDATED\n(End-to-End benchmark audit complete)"]
    
    A -->|Contradicted by source / failed empirical probe| INV["INVALIDATED\n(Hypothesis refuted & preserved for record)"]
    V -->|Empirical failure at scale / theoretical flaw| INV
```

1. **`ASSERTED`**: The claim has been identified from literature, framework documentation, or initial AI-assisted reconnaissance, but has not yet been isolated and tested in code.
2. **`VERIFIED`**: The claim has been confirmed through manual primary-source inspection, raw tensor weight examination, legal gazette review, or an isolated standalone script execution (may depend on external datasets/artifacts).
3. **`REPRODUCIBLE`**: The claim is codified as a permanent, deterministic mathematical contract, ground-truth test, or CI fixture directly within the repository test suite.
4. **`IMPLEMENTED`**: The claim's functionality is fully implemented in production core modules (`src/bias_aperture/`).
5. **`VALIDATED`**: The claim is end-to-end validated on the full 97,698-image FairFace benchmark audit.
6. **`INVALIDATED`**: A working hypothesis or prior assumption was tested, found false, and preserved as a documented research finding rather than silently deleted.

## 3. Invalidated Claims (Research Failures & Refutations)

Preserving refuted hypotheses is an essential research integrity discipline. The following claims were initially considered or asserted in prior documentation and subsequently **invalidated**:

| Invalidation ID | Original Working Hypothesis | Refutation Evidence & Method | Architectural Consequence |
|:---:|---|---|---|
| **INV-001** | *FairFace preprocessing relies on MTCNN for face detection and bounding box alignment.* | Source code inspection of official `dchen236/FairFace` `predict.py` confirmed usage of `dlib.cnn_face_detection_model_v1` and `dlib.get_face_chips(size=300, padding=0.25)`. | Removed MTCNN dependency; aligned input pipeline with dlib 5-point alignment. |
| **INV-002** | *`scipy.stats.bootstrap(method='BCa')` could be used directly without a custom engine in our multi-group pipeline.* | Evaluated in our initial environment; multi-group disparate metrics required fixed-strata resampling and custom schema formatting not directly supported by standard single-array call signatures. | Designed and implemented dedicated vectorized BCa bootstrap engine with fixed-strata resampling and jackknife delete-$d$ acceleration. |
| **INV-003** | *AIF360 and Fairlearn natively implement identical mathematical definitions for Equalized Odds Difference.* | Empirical evaluation revealed Fairlearn computes $\max(\Delta\text{TPR}, \Delta\text{FPR})$ while AIF360 native computes $\frac{1}{2}(\Delta\text{TPR} + \Delta\text{FPR})$. | Harmonized `AIF360Backend` to calculate worst-case max-gap from raw TPR/FPR primitives. |
| **INV-004** | *UTKFace can serve as a drop-in secondary validation benchmark alongside FairFace.* | Taxonomy analysis showed UTKFace collapses East/Southeast Asian categories (3/7 race match) and uses DEX model-predicted noisy ages. | Formally cut UTKFace per Cut-List #2 to avoid invalidating the locked 7-race schema. |
| **INV-005** | *Dual-backend execution (Fairlearn + AIF360) constitutes independent statistical validation.* | Methodological analysis proved both libraries compute over identical confusion-matrix primitives; agreement reflects heterogeneous software cross-checking, not statistical independence. | Reframed novelty claim around implementation cross-checking rather than independent statistical estimation. |
